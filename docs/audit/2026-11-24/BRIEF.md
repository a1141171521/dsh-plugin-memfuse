# 审计统一说明（2026-11-24 全量找 bug）

## 目标

在 `<REPO_DIR>`（git `9b6d190`，现有 188 项测试全绿）里
**找出真机上用户能看见的隐藏缺陷**，并给出可复现证据。

这是给真实用户用的 DSH 长期记忆插件。用户的原话是：
「不要让我一个一个去发现 bug 了」——所以宁可报得细，也不要漏。

## 铁律

1. **只读审计**：不得修改 `lib/`、`test/`、`package.json`、`docs/spec.md`、`docs/NEXT.md`、`AGENTS.md`。
   只允许写两个地方：
   - 自己的报告：`docs/audit/2026-11-24/<你的区域>.md`
   - 临时脚本/夹具：`.audit/<你的区域>/`
2. **绝不碰真实记忆库**：不要读写 `%USERPROFILE%\.dsh\memory`、`~/.dsh/sessions`、`~/.dsh/state.json`。
   所有实验都在临时目录里做，例如 `node -e "process.env.DSH_HOME='<临时目录>'; ..."`。
   需要真实数据做样本时，**先复制**一份到 `.audit/<区域>/` 再用。
3. **不做 git 操作**（不 commit / 不 push / 不 checkout / 不 stash）。
4. **无证据不写**：每条 finding 必须有最小复现（脚本路径 + 命令 + 实际输出/断言）。
   "这段代码看起来可能有问题" 不算 finding，要么写出复现，要么写在「未能证实」一节。
5. **别把设计报成 bug**：先读 `docs/spec.md` 对应章节和 `docs/NEXT.md` 顶部 200 行。

## 已知设计（不是 bug，别报）

- P0 记忆常驻注入、且即使与查询无关也进 Block A。
- 技能卡片是两段式（点提炼 → 当场调模型出草稿 → 装/丢）；行数跟 `skill.suggestMax`（默认 1）。
- 卡片「看过」= DOM 可见后才确认，不是渲染即记。
- 只有「上次确认之后有新内容」的簇才弹卡片（缺陷 41 之后的行为）。
- 休眠（dormant）记忆只在真实词法命中时召回并自动唤醒。
- 自动抽取暂停是**模型配置**问题（推理模型烧 maxTokens），不是代码 bug。
- 单 store 唯一 owner：与 dsh-memory 同时启用会双份注入，属预期限制。

```markdown
## 发现

### F-<区域缩写>-01 <一句话标题>
- 严重度：blocker | high | medium | low
- 位置：lib/xxx.js:123

## 未能证实（可疑但没复现出来）
- ...

- ...
```

## 严重度口径

- **blocker**：用户可见的错误 / 丢数据 / 静默失效（功能存在但从不生效）/ 崩溃 / 卡死。
- **high**：特定常见路径下出错、状态不一致、错误被吞掉、明显的数据错配。
- **medium**：边界条件错误、体验缺陷、性能问题（有量化）。
- **low**：文案、日志、代码整洁、极端边界。
